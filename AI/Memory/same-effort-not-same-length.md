---
name: same-effort-not-same-length
description: Balance in a node means both sides got the same chance and the same care. It never means equal length or an equal count of reasons.
metadata:
  type: feedback
---

Not every argument has as much for it as against it. Some arguments are simply better than others, and a node that reads lopsided may only be reporting a lopsided field. What has to be equal is the effort: the best published defender of each side is named, the best source behind each sits at the same tier and register, and each is stated as fully as its sources carry. A counter cut short to fit, or answered before it has been stated, fails. A counter that is thin because the literature is thin passes, and the node says so.

**Why:** set by the user on 2026-09-18 when the pipeline gained an "effort check" on the verifier. The first draft of that check read as "is the counter written as well and as fully as the main argument", which would have pushed the writer toward padding the weak side. The user's correction: imbalance is natural, both sides get the same chance and effort, and that is the whole test. It sits beside the false balance guard in `references/balance.md`, which already forbade manufacturing a two sided debate.

**How to apply:**

- Rule 9 in `.agents/skills/source-node/references/balance.md` is the wording. The verifier's effort verdict is `same effort`, `less effort on the main case` or `less effort on the counter`, never a word count.
- When a counter is short, ask whether the sources ran out or the writer did. Only the second is a failure.
- Never add a reason to the thin side to even things up, and never trim the strong side. See [[evidence-nodes-are-facts]] for the same instinct on evidence notes.
